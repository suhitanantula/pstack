# Starter Paths — pstack for Rotman Business Design

Five ready-to-run entry points into the 5Ps of Loop Design. Each one names where to start, what to do, and what you'll have at the end.

The 5Ps are a loop — you can enter at any point. These paths give you a clear on-ramp for the most common situations.

---

## Path 1 — New Venture / Design Challenge
*Full loop — fuzzy brief to designed solution*

**When to use:** You've been given a challenge and don't yet know what the real problem is.

**Loop sequence:**
```
Perceive → Perform → Portfolio → Pause/Promote → Progress
```

**Step by step:**

**1. Perceive** — Who are the people? What's actually going on?
- Map who is affected (primary, secondary, hidden)
- Find the problem behind the problem
- Output: reframed problem statement + the unseen thing

**2. Perform** — Take an intentional first move
- What is the smallest thing we can make to test our understanding?
- Build it (mock-up, scenario, concept sketch) and put it in front of a real person
- Output: a testable prototype + what we learned from testing it

**3. Portfolio** — Map the live options
- What are the distinct directions this design could go?
- For each: what assumption does it rest on?
- Output: 3 live options with different assumptions, actively maintained

**4. Pause/Promote** — Choose what moves forward
- Run both filters: analytical (what does the evidence say?) and resonance (what aligns with what we value?)
- State what you're promoting, what you're pausing, and why
- Output: a clear decision with stated parameters and what would change it

**5. Progress** — Build the learning system
- What did this loop teach us about the people, the process, and the AI + human combination?
- Feed the next loop's Perceive
- Output: Progress report + updated sprint log

**Time:** Full semester arc or a 2-day intensive

## Path 2 — Customer Empathy Sprint
*Perceive-heavy — understand before building*

**When to use:** Your team knows the domain but not who you're really designing for.

**Loop sequence:**
```
Perceive (deep) → Portfolio (light — 3 problem frames) → Pause/Promote
```

**Step by step:**

**1. Perceive (extended)**
- Spend most of this session here
- Primary question: Who are the people this design will affect, and what are they actually experiencing?
- Use both what's documented AND what human members of the team know firsthand
- Surface the problem behind the problem

**2. Portfolio (light)**
- Don't generate solutions yet — generate 3 ways of framing who you're designing for
- Not "3 features" — "3 different understandings of the core need"
- Example: Frame A: the problem is access. Frame B: the problem is trust. Frame C: the problem is time.

**3. Pause/Promote**
- Which frame has the most resonance — both analytically and intuitively?
- What does each frame imply about what to design?

**Output:** A validated Perceive artifact — reframed problem, stakeholder map, chosen frame for the next loop

**Time:** One session (2–3 hours)

## Path 3 — Strategic Options Review
*Have directions, need to choose*

**When to use:** The team has 2–3 directions but is stuck on which to pursue.

**Loop sequence:**
```
Portfolio → Pause/Promote
```

**Step by step:**

**1. Portfolio — Make each option tangible**
- For each direction, create a brief expression: what does it look like? what does it feel like to the person using it?
- For each: "What would we have to believe for this to work?"
- For each: "If we pursued this and it failed, what would we learn?"

**2. Pause/Promote — Filter through both dimensions**
- Analytical filter: which option has the most evidence? the most tested assumption?
- Resonance filter: which option feels most aligned with what you're actually trying to do?
- Name what you're NOT pursuing — this is as important as what you are

**Output:** A clear direction + the "not pursuing" list with honest reasoning

**Time:** One session (90 min – 2 hours)

## Path 4 — Rapid Prototype Session
*Perform-heavy — prove the idea works*

**When to use:** A direction has been chosen. Now you need to make it real fast and learn from it.

**Loop sequence:**
```
Perform → Progress → (return to Portfolio if needed)
```

**Step by step:**

**1. Perform**
- Define done before you start: "What is the smallest artifact that would tell us whether this idea works?"
- Build it — in business design this might be a service blueprint, a scenario walk-through, a one-page value proposition, or a mock interface
- Test it with one real person. Watch what they do. Ask what was unclear.

**2. Progress (quick)**
- What did this prototype teach you?
- Did it confirm the direction, or reveal a problem?
- If it confirmed: what's the next move?
- If it revealed a problem: which option in the Portfolio becomes more interesting now?

**Output:** A tested prototype + a clear learning from contact with reality

**Time:** 1–2 days

## Path 5 — End-of-Project Learning Debrief
*Capture what the team learned — for yourselves and for what comes next*

**When to use:** A project milestone is reached or the semester is ending. The team needs to crystallise learning before dispersing.

**Loop sequence:**
```
Progress → Observer (brief) → Perceive (light — what new questions emerge?)
```

**Step by step:**

**1. Progress**
- Gather outputs from the loops you've run
- Answer across three layers: design learning, process learning, AI + human learning
- What happened vs. what you expected?

**2. Observer (brief)**
- Zoom out from the individual loops: what patterns appeared across the whole project?
- Which Ps did the team use confidently? Which were avoided or felt difficult?
- What does the team know now about how they design together?

**3. Perceive (light)**
- If there's a next challenge: what does what you learned suggest about where to start?
- What question are you now asking that you weren't asking at the start?

**Output:** A 1-page learning brief that a future team (or your future self) could use to start smarter

**Time:** One session (1–2 hours)
